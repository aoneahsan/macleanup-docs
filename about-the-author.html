About and contact

macleanup is built and maintained by the macleanup team. The command line is MIT-licensed open source; the desktop app runs that same script.

The macleanup team

  • Email — aoneahsan@gmail.com
  • Issues — github.com/aoneahsan/macleanup/issues
  • Website — macleanup.aoneahsan.com
  • More from the team — aoneahsan.com

Getting in touch from the terminal​

Three flags, all local-first. Nothing is auto-sent — you review every prefilled message before submitting it.

macleanup --contact         # the contact card
macleanup --feedback        # opens your mail client, prefilled
macleanup --report-issue    # opens a pre-filled GitHub issue
macleanup --stats           # your run history under ~/.macleanup

--report-issue gathers the version, macOS version and chip, RAM, bash and Node versions, and the latest log path — entirely on your machine. When pbcopy is available, the last 50 log lines land on your clipboard so you can paste them into the issue. Nothing reaches GitHub until you press Submit.

If a run exits with an error, the script prints a hint pointing at --report-issue, so you do not have to remember the flag.

Reporting a bug​

Open an issue at github.com/aoneahsan/macleanup/issues, ideally via macleanup --report-issue so the environment details come along.

A good report names the version, the exact command, what you expected, what happened, and the relevant log lines from ~/.macleanup/logs/.

Reporting a security issue​

Privately, by email to aoneahsan@gmail.com — not a public issue. Path traversal, an unintended rm -rf, or a data-leakage scenario all qualify. See SECURITY.md.

This project deletes files, so a security report here can be a data-loss report. Both are welcome, and both are taken seriously.

Contributing​

macleanup is MIT-licensed open source. Issues and pull requests are welcome, though acceptance is at the maintainers' discretion. See CONTRIBUTING.md and the Code of Conduct.

The whole tool is two readable files — macleanup.sh in plain bash and a short Node launcher — so a first contribution does not require learning a build system.

About this documentation site​

This site is open source too. If a page is wrong, unclear, or missing something you needed, every page has an Edit this page link at the bottom, or you can open an issue at github.com/aoneahsan/macleanup-docs.

Documentation for a tool that deletes files has one job above all others: let you know what will be removed before you run it. A page that fails at that is a bug worth reporting.
