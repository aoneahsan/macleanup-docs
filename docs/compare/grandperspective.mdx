# Moving from GrandPerspective

If you like reading your disk as a tree map, you don't need to move at all.
GrandPerspective is free, and macleanup draws nothing like it. Where the two meet is the moment after the
scan: GrandPerspective shows you a large block and leaves the question of whether it
is safe to remove with you. A numbered section already knows what that block is and
what removing it costs.

## From a coloured block to a section number

| In GrandPerspective | In macleanup |
|---|---|
| Tree map of disk usage | [Section 26](/reference/sections#section-26--disk-usage-report), text only |
| Finding big files | [Section 18](/reference/sections#section-18--large-files-report), no age filter |
| Delete from the view | [Section 24](/reference/sections#section-24--large-stale-files), to the Trash, with confirmation |
| That huge `node_modules` block | [Section 23](/reference/sections#section-23), deleted permanently |

## Using the map and the script together

1. Scan in GrandPerspective and write down the three largest blocks. Then hand
   the question to the audit profile.

   ```bash
   npx macleanup --profile audit --dry-run
   ```

2. One of them a build folder? Preview section 23 with a threshold of your own.

   ```bash
   npx macleanup --only 23 --stale-build-days 90 --dry-run
   ```

3. Sitting in `~/Library/Caches`? That is user caches.

   ```bash
   npx macleanup --only 5 --dry-run
   ```

4. Before section 23 runs for real, shield any project you would hate to rebuild
   with `--exclude-path`, described in [Stale build artefacts](/reference/sections#section-23).
