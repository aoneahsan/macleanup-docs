5.3.0 — an assistant, receipt backups and required updates

30 October 2026

Section 26 (disk usage report) no longer measures ~/Music, ~/Movies or ~/Pictures, so the desktop app no longer asks for Apple Music, media or Photos access on a first preview. The report says they were not measured. In the desktop app: an assistant that explains a preview, typed or spoken; receipt backups on Pro and Team; and required updates. Automatic updates now relaunch at a quiet moment, never during a run.

5.2.2 — keep means keep, a faster large-file scan

30 October 2026

--exclude-path now keeps a path in every bulk wipe and age-based prune, not only in the per-item deletes; a folder that holds a kept path is left whole. Section 18 skips photo libraries, iCloud folders, Movies, Music, virtual machines and the Trash instead of walking them, so the scan takes seconds. The script is split into an entry file and short modules in lib/; what it does is unchanged. Output names the macleanup team instead of a person. In the desktop app, scheduled runs now report back with a receipt.

5.2.1 — package page refresh

30 October 2026

README and package metadata only: the npm page shows the current version and size and links the website as the homepage. The script is unchanged.

5.2.0 — the desktop app and a toolchain inventory

30 October 2026

The macleanup desktop app for macOS ships with this release: one disk image for Apple silicon and Intel Macs, running this same script with a disk gauge, a dry-run ledger and a receipt for every run. Section 0 (system health, read-only) lists installed developer toolchains — Node versions under nvm, pyenv Pythons, rbenv Rubies, rustup toolchains, Java VMs, Xcode, the Android SDK and Studio, Docker Desktop, Flutter and Homebrew — with the space each takes. It changes nothing. In the JSON event stream, each item carries age_days, toolchain items carry tool and version, and section 5 names each cache folder it would clear. The schema stays at version 1.

5.1.0 — event stream, archives and run accounting

30 October 2026

--json-events prints a newline-delimited JSON event stream on stdout while the run happens: plan, disk, section_start, item, progress, section_result, error and summary. Schema version 1 is on the JSON event stream page. The macleanup desktop app reads this stream. --archive-path PATH (repeatable) writes PATH to a gzip archive in ~/.macleanup/archives/ before it is deleted or moved to the Trash. The folder is mode 700 and each archive mode 600. If the archive cannot be written, PATH is left in place. --exclude-path now protects a path in every section's delete and Trash move, not only in sections 23 and 24. --all runs its safe-batch sections through the same dispatcher as --only, so every run uses one accounting path. The session summary counts attempted, skipped and failed sections beside the completed ones. It also shows the local-snapshot count, with a note that deleted files may not free space until macOS releases those snapshots. Section 12 lists the orphan-shaped entries it skipped because they were touched recently, in its report, for review. A skipped entry is not proof that nothing is left behind. Section 25 lists loaded Homebrew and third-party services in both launchd domains, your user's and the system's. brew services list in one domain can say none while a root service is running. The launcher is verified on Node 14.21.3, so the declared engines.node floor of >=14 holds. The macleanup desktop app is being released alongside 5.1.0. It runs this same script.

5.0.0 — one name: macleanup

29 October 2026

The command, script, data folder, config file and environment variables all use one name: macleanup, macleanup.sh, ~/.macleanup/, ~/.macleanuprc and MACLEANUP_*. Run it as macleanup or npx macleanup. The second command name that earlier versions installed is gone. Scripts and shell aliases that called it need to call macleanup instead. The first 5.x run copies an existing 4.x data folder into ~/.macleanup/ and leaves the original in place. The 4.x config file and environment variable names are still read for 5.x, with a note asking you to rename them. The package no longer declares a main entry, so importing macleanup from Node fails instead of starting the cleanup tool. See Upgrading to 5.0 for the full table.

4.7.1 — launch-item audit correction

26 October 2026

Section 25 preserves spaces in structured LaunchAgent program paths. It no longer reports an existing target such as one under Application Support as missing. Ambiguous raw plist strings are skipped; genuinely missing targets still appear in the audit. Section 25 is report-only in batch mode unless both --yes and --i-understand-deep are supplied. The interactive menu always asks which candidates to remove. Previously, --yes alone selected and removed every reported stale launch item.

4.7.0 — safety release

23 October 2026

The minimal profile no longer selects Empty Trash. Section 10 now needs both --yes and --i-understand-deep when run unattended. A refused deep section no longer appears as completed in the run summary. Section 8 leaves ~/tmp and nested temp entries alone. It removes only old, top-level regular files from the system temp locations. Sections 12 and 21 leave affected data in place when Finder cannot move it to the Trash. They no longer fall back to permanent deletion.

4.6.3 — patch

25 July 2026

Corrected the README version row to match the published package version.

4.6.2 — licensing and documentation

25 July 2026

Changed the package license to MIT. Reworked the README to make destructive behavior, recovery limits, and the package's public interface clearer.

4.6.1 — patch

8 June 2026

A dry run now estimates the space it would free. Previously --dry-run reported freed_kb: 0: it printed per-folder "would clear …" notes but never tallied a total, so previews showed 0 B. The cleanup helpers and section 5 now measure what they would delete and report the estimate. --json lists only this run's report files. It previously included every file in the reports directory, leftovers from earlier runs the same day included; it now filters to files written during the current run.

4.6.0 — GUI privileged operations and UX

8 June 2026

One admin prompt per run for the desktop GUI. When launched by the companion macOS app, the CLI routes sudo through a graphical askpass, so privileged sections (6, 7, 9, 11, 13, 14, 20) actually run from the GUI and ask for the password once. They previously skipped silently, having no terminal to prompt on. Terminal users are unaffected. --dry-run no longer attempts privilege elevation — a preview never prompts for a password; only a real run does.

4.5.1 — patch

8 June 2026

--flag=value is accepted, alongside --flag value. A token like --cache-age-days=30 was previously rejected with exit code 2. Clearer unknown-option errors — the offending option plus a one-line hint, instead of dumping the whole help text.

4.5.0 — safety, correctness, features

8 June 2026

A broad audit-driven release, with two behaviour changes that matter to unattended users. Ctrl-C now actually aborts. The combined exit/interrupt trap returned without exiting, so on SIGINT/SIGTERM bash ran cleanup and then resumed the interrupted operation — including a destructive one. --i-understand-deep introduced. The deep sections (6, 11, 14, 21, 24) now need this flag in addition to --yes to run unattended. --yes alone no longer enables them, and --all never does. Section 13 removed from the --all safe batch. Running sudo periodic unattended is privileged system maintenance, not cache cleanup. Section 27 added — QuickLook and font caches. Menu / --only only. --json one-line run summary for scripting and CI. --exclude-path PATH — repeatable, protects a tree from sections 23 and 24. --prune-history [N] and --uninstall-data for housekeeping. Config file ~/.mac-cleanuprc — defaults in key = value form, overridden by any explicit CLI flag.

4.4.2 — safety patch

13 May 2026

Defensive hardening of the CRITICAL_HOME_DIRS allowlist, making the pnpm and corepack protections explicit so a future change cannot silently regress them. No behaviour change for anyone whose section 23 had been working correctly.

4.4.1 — documentation release

10 May 2026

A complete end-user documentation set under docs/ in the source repository. No script behaviour changed.

4.4.0 — user-facing polish

10 May 2026

Feedback channels became first-class, with the no-telemetry promise unchanged — nothing is ever auto-sent. --contact — the author contact card. --feedback — opens your mail client with a prefilled message. --report-issue (alias --report-bug) — collects environment info entirely locally, opens a pre-filled GitHub issue, and copies the last 50 log lines to the clipboard. Nothing is transmitted until you click Submit. --stats — a read-only summary of ~/.mac-cleanup/.

4.3.3 — the two-condition rule

10 May 2026

Anything that is not pure cache must now satisfy both conditions before it is deleted automatically: not in use by any installed software, and untouched (atime and mtime) for at least --idle-days days, default 100. This closed the failure mode where the first condition held but the second was never checked — a container directory whose owning app could not be matched by bundle id, but which something was still touching. Applies to sections 12, 21, 23 and 24.

4.3.2 — age-aware cache pruning

10 May 2026

Sections 1, 2 and 3 stopped wiping entire caches. They previously deleted every file regardless of recent use, which is what produced reports like "my Gradle distribution disappeared". They now keep anything whose atime or mtime is inside --cache-age-days.

4.3.1 — safety fix

10 May 2026

Anyone still on 4.3.0 should upgrade. Section 23 no longer enters toolchain or config directories. 4.3.0 could match node_modules-shaped folders nested inside ~/.bun, ~/.pnpm-store, ~/.local/share/pnpm, ~/.npm-packages, ~/.volta, ~/.asdf and similar, and selecting "all" then broke globally installed tools. Fixed with a hard CRITICAL_HOME_DIRS allowlist of 35+ entries. No silent $HOME fallback. Section 23 now errors out and asks for --scan-roots when it cannot find a standard dev folder. brew autoremove became opt-in via --brew-autoremove. Recovery instructions for machines affected by the 4.3.0 behaviour: Recovery.

4.3.0

10 May 2026

The release that introduced the section 23 bug fixed in 4.3.1. Added profiles and several flags. Do not run this version.

4.2.0 — zero-install distribution

9 May 2026

Published to npm as macleanup, so npx macleanup works with no install. A dependency-free bin/mac-cleanup.js launcher validates Darwin and spawns bash. Both macleanup and mac-cleanup are registered as bin names. Persistent logs and reports moved to ~/.mac-cleanup/{logs,reports}/, out of the repo directory that npm's cache reclaims after an npx run. A branded credits header was embedded in every log and report. New --logs-dir, --reports-dir, --no-reports, --cleanup-logs-on-finish.

4.1.0 — four new sections

9 May 2026

Section 23 — stale build artefacts (node_modules, vendor, dist, build, .next, .nuxt, .turbo, .vite, .parcel-cache, .svelte-kit, .astro, .cache, target, Pods, coverage, .nyc_output), sorted by size with multi-select bulk delete. Section 24 — large stale files, moved to the Trash for safety. Section 25 — LaunchAgents / LaunchDaemons audit. Section 26 — disk-usage report. New --scan-roots, --list, --version, --no-color; multi-select in section 21; hardened path quoting and a bash-version and macOS preflight.

4.0.0 — single-file rewrite

17 April 2026

A complete rewrite into one self-contained mac-cleanup.sh, replacing the previous modular split and four standalone legacy scripts. Identical feature set, with one state, logging and prompt model — and one safe_rm_rf, one clean_dir_contents and one confirm helper shared by every section. --all stopped auto-running destructive sections, limiting itself to the read-only and cache-only sweeps. --threshold N was added, along with per-day rolling logs.
