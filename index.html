macleanup

A safe-by-default macOS cleanup CLI with 28 targeted sections, confirmation by default, and a dry run that deletes no files.

npx macleanup --dry-run --all
See what it deletesInstall
macleanup permanently deletes files. Most of what it removes is regenerable cache, but not all of it is — read what gets deleted and preview with --dry-run before your first real run.

What it removes

Twenty-eight numbered sections, each one chosen from a menu or by number. Nothing runs that you did not select.

Developer caches

Xcode DerivedData and simulators, Gradle and Android caches, and the package-manager caches for npm, yarn, pnpm, Homebrew, pip, CocoaPods, cargo, go, Ruby and Flutter. All regenerate on next use.

System, user and browser caches

~/Library/Caches and Saved Application State, /Library/Caches (sudo), and the cache directories of Chrome, Brave, Edge, Vivaldi, Chromium, Opera, DuckDuckGo, Arc and the Firefox family. Bookmarks, history and passwords are not touched.

Logs, temp files and update caches

Old user and system logs, $TMPDIR / /tmp / ~/tmp entries you own, and downloaded update caches. Trash is emptied only when you say so.

Stale build artefacts

node_modules, vendor, dist, .next, target, Pods and similar directories inside your scan roots — but only when they have been untouched (atime AND mtime) for the full idle threshold.

Orphaned app data and unused apps

Leftover application-support and container data with no installed app, and applications idle past your threshold. Apps go to the Trash, so they are recoverable until you empty it.

Reports, not deletions

Several sections only look: system health, installer leftovers, large files, LaunchAgents audit and a disk-usage report write a dated .txt to ~/.macleanup/reports/ and delete nothing.

How it avoids surprises

The guarantees below are real, and they are not a substitute for a backup. macleanup runs rm -rf and sudo on your machine, and you are responsible for verifying its output.

--dry-run deletes nothing

Every destructive helper checks the flag and prints what it would remove instead of removing it. Since 4.6.1 a dry run also estimates the space that would be freed.

Per-section confirmation

Destructive operations prompt before running unless you pass --yes. Section 14 additionally requires a typed "yes" and a reboot afterwards.

The deep sections never auto-run

Sections 6, 11, 14, 21 and 24 are refused in batch mode unless you add --i-understand-deep on top of --yes. --all (even --all --yes) never runs them.

Two conditions before a non-cache delete

In sections 12, 21, 23 and 24 an item is removed automatically only when it is both unused by any installed tool and untouched for at least --idle-days days.

Toolchain directories are off limits

A hard allowlist stops section 23 entering ~/.bun, ~/.pnpm-store, ~/.volta and friends, and it refuses to scan without explicit roots rather than falling back to your entire home directory.

No telemetry

The script makes no network calls. The single exception is the opt-in --check-update, an unauthenticated GET to the npm registry that sends no data about you.
